# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project is

A GATT-to-MQTT bridge for the **ATORCH DT24pw** USB power meter. The binary connects to the DT24 over BLE, decodes its proprietary notification frames, and republishes voltage/current/temperature/capacity to a Mosquitto broker. Derived from BlueZ v5.39's `tools/btgatt-client.c` (via gbrault/gattclient) — most files under `src/` are unmodified BlueZ sources; DT24-specific logic lives in `btgattclient.c` and `mqtt.c`.

## Build & run

Plain Makefile, no autotools/cmake. All work happens in `src/`.

- `make` — builds the `gattclient` binary.
- `make clean` — removes `*.o`, `*.d`, the binary, core files.
- `make install` — installs to `/usr/local/bin` (runs `install` as root).
- `make format` — runs `astyle -A2 -p -xg -k2 -W2` on all `*.c`/`*.h`.
- `make check` — runs `cppcheck --enable=all --inconclusive --std=c11`.
- There is no test suite.

Runtime deps (linked via pkg-config / `-l`): `glib-2.0`, `pthread`, `m`, `crypt`, `rt`, `mosquitto`. Build is `-Wall -Werror -Wfatal-errors -Wextra -std=c11` — warnings fail the build.

Typical invocation: `./gattclient -d <BLE_MAC>` (see `-h` for all flags). Notable non-BlueZ flags added by this fork:

- `-D` — disable MQTT publishing (local/dev mode).
- `-c` — disable interactive console (daemon mode; logs go to syslog via `dlog`).
- `-H <hostname>` — overrides the hostname used in MQTT topics (`tele/<host>/STATE|SENSOR|LWT`).

When the console is enabled, the prompt accepts BlueZ-style commands (`help`, `services`, `read-value`, `write-value`, `register-notify`, …) plus project-specific `rssi [interval_ms]`, `batt [interval_ms]`, and `quit`. The command table is in `btgattclient.c` around the `command[]` array.

## Architecture

Three layers, loosely stacked:

1. **BlueZ GATT/ATT stack (unmodified vendored code).** `att.c`, `gatt-client.c`, `gatt-db.c`, `gatt-helpers.c`, `bluetooth.c`, `hci.c`, `uuid.c`, `queue.c`, `crypto.c`, `io-mainloop.c`, `mainloop.c`, `timeout-glib.c`, `util.c`. Treat these as upstream — avoid editing unless porting a BlueZ fix. `mainloop.c` is an epoll-based event loop; everything in the app is driven by its fd/timeout/signal callbacks.

2. **Daemon utilities (`d*.c`).** `dlog` (syslog logging — use `daemon_log(LOG_*, …)`), `dfork`/`dpid`/`dsignal`/`dexec` (daemonization, pidfile, signal handling, child process exec), `dmem`, `dnonblock`. Used to run the binary as a proper daemon when `-c` is set.

3. **App glue: `btgattclient.c` + `mqtt.c`.** This is where DT24 behavior lives.
   - `subscribe_chrc()` (in `btgattclient.c`) inspects each characteristic during service discovery and registers notify handlers for two hardcoded UUIDs: `0xe1ff0000` (DT24 telemetry stream) and `0x192a0000` (battery). If the device firmware changes these UUIDs, subscription silently does nothing.
   - `notify_cb()` reassembles the DT24's fragmented telemetry into a 36-byte frame starting with `ff 55`, then decodes voltage (×0.1 V), current (×0.001 A), temperature, and Ah/Wh capacity using `dl24_get_{16,24,32}bit` helpers. Byte offsets are DT24-specific and undocumented beyond the reference project (`syssi/esphome-atorch-dl24`) cited in the root README.
   - `mqtt.c` runs a Mosquitto client on its own pthread. `mosq_gather_data()` accumulates samples; `mosq_publish_state()` averages and publishes on a ~10 s interval. Broker defaults (`mosquitto:8883`, TLS, user `owntracks`) are hardcoded at the top of `mqtt.c` — change them there if the deployment differs.

The top-level `main()` in `btgattclient.c` is a reconnect loop: it opens an L2CAP LE-ATT socket, runs the mainloop, and on exit sleeps (60 s) before reconnecting unless `terminate` was set by SIGINT/SIGTERM. Battery/RSSI periodic polls are implemented as mainloop timeouts stored in `batt_timer_fd` / `rssi_timer_fd`.

## Conventions worth knowing

- Logging goes through `daemon_log()` or the `PRLOG`/`PRLOGE` macros in `btgattclient.c`, which route to syslog when `disable_console` is set and to stdout/stderr otherwise. Don't bare-`printf` from new code.
- `config.h` is a checked-in BlueZ-generated header from the 5.31 tree; don't regenerate it.
- `version.c` is generated by `make` from `git describe` (see the Makefile's `version.c:` rule), but no target actually depends on it currently — it's effectively unused.
